# W5: Mode 3 per-generation census (D1'-full): aligned-window engine, non-inductive pinning, LockstepPackageGen, and a timed erasure layer that makes erasure load-bearing

## Goal statement

Deliver, additively, the per-generation census the lockstep design promised: a new package LockstepPackageGen whose budget fields are PackageB's {rentBound, erasure_freeze-shaped genBound, budget_le} (no cumulative exposedBound at all), a new validator-agnostic aligned-window engine window_shared_prefix (the generalisation of horizon_shared_prefix to an arbitrary window matured in both chains), a NEW non-inductive per-window pinning theorem, new lockstep headlines at confirmation depth 2n that need no shared genesis, and a timed layer (stolenAt; NoPrematureTheftLock / ErasureTimedLock phrased against rosterGen ∘ (·/n), the roster's switch grid) in which ErasureTimedLock is CONSUMED by the derivation of genBound from a pre-retirement theft-rate. Answers to the three questions asked: (1) a pure budget-transport lemma (per-generation rates + erasure ⇒ LockstepPackage.exposedBound at lagSched) is NOT achievable — exposedBound at any window is a union over all future generations j ≥ rosterGen(W−1) and per-generation rates bound each j-slice by T but not the union; a machine-checked counter-witness (n=2, T=1, rosterGen ≡ 0, Stolen i j := i = j) is included — so the safety proof must change, and it changes by a NEW engine + NEW pinning theorem + NEW headlines placed next to the old ones (nothing existing is modified). (2) 'Generalising horizon_shared_prefix' concretely means: replace the fixed pigeonhole window u := tip.slot+1−n by an arbitrary u with maturity in both chains (u+n ≤ tip.slot+1 and u+n ≤ tip'.slot+1), restrict honest-slot uniqueness to that window (HonestSlotsUniqueOn u n), and replace hkdeep by 'the block at height k sits strictly below u' — the proof is the existing one minus the slot-gap step, plus public copies of the two private helpers; 'generalising the pinning lemma' means swapping the census from exposedBound-at-lagSched (which needed the induction hypothesis to discharge the ≥ lagSched side condition, and genesis_gen for window 0) to genBound at j := the window's declared generation g, which removes the induction, the lag, and the genesis base case entirely. (3) Depth 2n IS unavoidable for the aligned-window route in the worst case (exactly n + ((tip.slot+1) mod n) ≤ 2n−1 in positions): the last aligned window matured in the lower chain starts at ((tip.slot+1)/n − 1)·n, which can be as low as tip.slot + 2 − 2n; the core theorem is stated with an explicit window W and 'B.slot < W·n' so the sharp form is available for free, and the headlines use the clean 2n. Any depth-n statement would have to consult the sliding trailing window, which straddles the unpinned tip window where the two chains may declare different generations — that is the cumulative reading (D1'-thin) or a ρ+2T/3T factor loss, not a per-generation census.

## Alternatives rejected

- **Alt:** Pure budget-transport lemma: per-generation rates + (timed) erasure ⇒ LockstepPackage.exposedBound at lagSched, leaving lockstep_recent_tip_ancestor_agreement as the headline.
  - **Why rejected:** False. exposedProducersSched at lagSched over any window is the union over ALL generations j ≥ rosterGen(W−1) of the j-slices; per-generation rates bound each slice by T, not the union (counterexample n=2, T=1, Stolen i j := i=j; PackageB docstring:323-328). Timed erasure does not help: it confines each theft to its generation's live span but the union over future generations remains. Hence the safety proof must change (new engine, new pinning, new headlines) — additively.
- **Alt:** Keep depth n by running the pigeonhole at the sliding trailing window with a per-generation predicate on each of the two straddled grid windows.
  - **Why rejected:** The tip grid window is unmatured, so the two chains may declare different generations g ≠ g' there (each below quorum); the corruption predicate becomes chain-dependent or the census pays R + 2T (or 3T) — the D1 factor-2 wrinkle the design wanted to remove. The aligned route pays 2n depth instead of a factor in T; the owner chose D1'-full's shape (LOCKSTEP_DESIGN:214-218).
- **Alt:** D1 option (b): a relaxed agreement engine that needs only bad-count < quorum (using quorum > 2·maxByzantine) to absorb R + 2T.
  - **Why rejected:** Does not remove the chain-dependence of the tip window's predicate, and still counts two generations; it is a factor-recovery trick for the sliding window, orthogonal to (and weaker than) moving the pigeonhole inside the pinned region.
- **Alt:** Generalize horizon_shared_prefix in place (add a window parameter to the existing theorem) and re-route the existing callers.
  - **Why rejected:** Modifies an existing theorem and its callers — forbidden. The additive copy costs ~120 lines including the two private helpers, and an optional formal reduction shows the old lemma is the u := tip.slot+1−n instance.
- **Alt:** Express the switch times as an explicit function switchAt rosterGen j := Nat.find (∃ W, j ≤ rosterGen W) and state A3/B2 as j's switch time ≤ r < (j+1)'s switch time (literal 'j*R replaced by switch time').
  - **Why rejected:** Nat.find needs an existence proof, which fails for generations the counter never reaches (bounded rosterGen); phrasing A3/B2 pointwise against rosterGen (r / n) is total, equivalent for reached generations, and reduces to the flagship at rosterGen := id, R := n (the two _iff_flagship lemmas).
- **Alt:** Define the timed census as the exact-era census (∃ r, rosterGen (r/n) = j ∧ stolenAt i j r) and consume both A3 and erasure in the derivation.
  - **Why rejected:** Muddies the 'erasure is load-bearing' claim (A3 would be equally load-bearing). The pre-retirement census (rosterGen (r/n) ≤ j) needs erasure alone, the exact mirror of mode 2 where A3 alone is consumed; notBefore stays as a documentary field consumed by theft_in_era_lock, as notAfter is in mode 2.
- **Alt:** Horizon-scope the rent rate (∀ u, H ≤ u → …) with hH : H + 2n ≤ sTip.slot + 1, mode-2-timed style.
  - **Why rejected:** Deferred: the engine consumes one window, so the H-guarded form is a trivial follow-up package; adding H now would diverge the field shape from LockstepPackage.rentBound and enlarge the item without changing what is proved. Noted as a follow-up, not a loop.
- **Alt:** Keep `mono` and `genesis_gen` in LockstepPackageGen for parity with LockstepPackage.
  - **Why rejected:** Neither is consumed on the new route (non-inductive, genesis-free pinning); carrying unconsumed fields contradicts the codebase's honest-accounting habit (map notes that mono is already consumed by nothing). Left to the owner as a question since the paper's Theorem 5 prose lists them.
