# W1 — Mode 3 (free-cadence lockstep) at certificate level: GroundedCertLock with a one-counter threaded state, history reconstruction, certificate-level pinning, and lockstep_recent_certified_suffix_agreement by transport through the existing full-chain lockstep engine

## Goal statement (verbatim)

Deliver the certificate presentation of mode 3 additively. A new inductive GroundedCertLock (n) (Signed) (G) : CertClaim → Nat → Prop mirrors GroundedCertSched but replaces the scheduled pin by the no-mixing fold check against ONE threaded Nat g = the prefix tip's declared generation: each fold checks g ≤ b.keyIndex and (cl.tipSlot / n = b.slot / n → g = b.keyIndex), then sets the state to b.keyIndex. A Bool suffix check lockstepFrom n tipSlot g suffix (the analogue of keyMonoFrom / schedPinned-over-the-suffix) runs the same two-clause check along the suffix. The reconstruction lemma groundedCertLock_suffix_history rebuilds a full chain that is validChain-accepted, lockstepOk, G-rooted and blockwise Signed; since lockstepOk implies keyMonoOk (new lemma keyMonoOk_of_lockstepOk), the reconstructed SignedChain passes the FULL validSignedChainLock, so every existing full-chain lockstep theorem applies verbatim. Answers to the four questions: (1) Pinning cannot be GATED at fold time -- rosterGen is execution-level and unknown to any verifier -- but it is DERIVED at fold-state level: the fold carries exactly the state the no-mixing rule needs (tipSlot, already in the claim, plus the tip generation g), and the certificate-level pinning theorems (lockstep_cert_declares_rosterGen for every tail/suffix block in a matured grid window; lockstep_cert_gen_pinned for the certificate's own g once its grid window is matured by the suffix) are corollaries of lockstep_declares_rosterGen applied to the reconstructed recent full chain. No per-window generation table, no running counter, no lagged counter is carried: the lagged counter lagSched is proof-internal (the transport lockstep_validSignedChainSched), never wire data. (2) Transporting unchanged from the mode-2 certificate path: exists_signedChain_of_covered, validChain_append_suffix, windowCount_append, windowCount_filter_low, validChain_append_one, slot_le_tip_of_mem, strictSlots_of_checks, linksOk_isChain, blockAt_getLast, validChain_sound, and the consumer chain sched_deep_block_agreement_of_length + schedUnforgeable_of_core + packageA_byzantine_bounded, plus the lockstep engine lockstep_declares_rosterGen / lockstep_validSignedChainSched / LockstepPackage.toPackageA. NOT transportable: groundedCertSched_history / groundedCertSched_suffix_history (different inductive; their proofs are copied with the pin conjunct replaced by lockstepOk maintenance) and sched_recent_certified_suffix_agreement itself (its GroundedCertSched inputs at lagSched cannot be produced: the verifier does not know rosterGen, and intermediate prefixes are not recent so the EUF-CMA surface would not cover a per-fold pin). The agreement theorem is therefore a direct proof that routes: reconstruct -> lockstep_validSignedChainSched (full chain, once, at the recent tip) -> sched_deep_block_agreement_of_length at schedule lagSched n rosterGen with k := c.length + i -- i.e. the same consumer sched_recent_certified_suffix_agreement closes with. (3) The LockstepPackage budget needs NO restating: rentBound/exposedBound/budget_le are chain-independent (badSched at lagSched reads no chain), so the certificate theorem takes hP : LockstepPackage unchanged, with no AttestedHistory quantification (the mode-1 complication) -- the same simplification mode 2's certificate form enjoyed. (4) Beyond the plain claim the certificate attests the tip generation g ('claim and generation together', the one-Nat analogue of GroundedCertK's n-vector floor); and for n ≥ 2 this is provably redundant (groundedCertLock_gen_of_tail: the tip block is the last element of cl.tail, so g is a function of the claim and the joint-authentication contract is met by the claim alone); only n = 1 (empty tail) genuinely needs the extra counter. Unauthenticated g would be a real attack (g* = 0 lets a suffix block signed under a stolen retired-generation key pass, exactly mode 2's schedule* ≡ 0 attack), so the docstring records the wire contract as GroundedCertK's does.

## alternatives_rejected (verbatim)

- alt: Read the tip generation from cl.tail at fold time (no threaded state; the fold checks no-mixing against every tail block).
  - why: For n = 1 the tail is empty, so cross-window monotonicity against the prefix tip would go unchecked and lockstepOk of the reconstructed chain would be unprovable; a uniform threaded Nat is simpler to induct on and is provably redundant for n ≥ 2 (groundedCertLock_gen_of_tail), which gives the same zero-wire-cost result without a 2 ≤ n restriction.
- alt: Derive a GroundedCertSched at lagSched n rosterGen from GroundedCertLock and invoke sched_recent_certified_suffix_agreement literally.
  - why: Impossible for the verifier (rosterGen is execution-level, never wire data) and unsound as a proof strategy: a per-fold pin at lagSched would need lockstep_declares_rosterGen on every intermediate prefix, but the EUF-CMA surface covers only RECENT chains; intermediate prefixes are not recent. Pinning must be applied once, to the full reconstructed chain with the recent suffix tip -- which is exactly what routing through lockstep_validSignedChainSched then sched_deep_block_agreement_of_length does.
- alt: Re-prove the pinning census at certificate level (a cert-level lockstep_declares_rosterGen with its own counting).
  - why: Unnecessary: the reconstruction yields a full chain with genesis at index 0 and a recent tip, so the existing theorem applies unchanged; a re-proof would duplicate 170 lines and the private helpers.
- alt: A core lockstep validator (drop keyMonoOk) with core mirrors of the lockstep theorems, mirroring the mode-2 certificate path.
  - why: Not needed: lockstepOk (roster-wide monotone) implies keyMonoOk (same-producer monotone), so the FULL validSignedChainLock is reconstructible from certificate data; no core variant and no mirrors.
- alt: State the suffix check as (boundary check on s₁) ∧ lockstepOk n (s₁ :: srest) instead of the lockstepFrom fold.
  - why: Logically equivalent, but the fold is what a verifier runs, mirrors keyMonoFrom (KeyStealingCert.lean:159) and the TS bridge shape (keyMonoFromTs), and gives the one-block fold step of the history proof for free (s := [b]).
- alt: Restate the LockstepPackage budget over attestable histories (AttestedHistory-style, as mode 1's keyrot cert theorem).
  - why: badSched at lagSched reads no chain and LockstepPackage's rentBound/exposedBound are chain-independent, so the package is consumed verbatim; quantifying over histories would only weaken the statement for no gain.
- alt: Put the axiom guards inside the new module instead of a separate guard file.
