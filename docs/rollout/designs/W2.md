# W2 — Mode 1 anchored / trailing-5n client rule at the certificate presentation (GroundedCertK + suffix), as a corollary of a generic-Signed anchored deep-block engine applied to the reconstructed chains

Source of record: `/etheron-pod/rollout-work/designs/W2.json` (verbatim design object; this digest compresses only outlines, proof sketches and reuse lists).

## Goal statement (verbatim)

Prove, additively and axiom-clean, that two verifying GroundedCertK certificates each extended by a validated recent suffix agree on every block at the same global height that is n-deep in both suffixes, with the corruption budget consulted ONLY on windows ending after a client anchor A (core form), and derive from it the Molt-level refresh-rule family at the certificate presentation: an H-parametric form (mirror of Molt.client_refresh_rule), the trailing-5n form with the previous sync itself in certificate form (mirror of Molt.stay_recent_client_safe), and the Δconf := n sync rule (mirror of Molt.sync_rule). Answers to the item's questions, all confirmed against source: (1) the anchor enters as membership in the EXPOSED SUFFIX (hA : A ∈ s₁ :: srest, hA' : A ∈ s₁' :: srest'), lifted to the reconstructed chain by List.mem_append_right; it need not and cannot usefully be located inside the certified prefix (the verifier cannot check that), and the protocol reading is 'the prover starts the suffix at or before the client's anchor' (≤ 4n slots back under the sync rule, so still O(n) blocks); (2) the confirmed floors are read as inForce over the RECONSTRUCTED chain inside badKeyrotOn c, exactly as in keyrot_recent_certified_suffix_agreement, with the budget quantified over AttestedHistoryK; the floor snapshot fl enters only through GroundedCertK/keyMonoFrom and is never consulted by the budget (a verifier-visible floor-based budget predicate is sound only for slots s ≥ cl.tipSlot + Δconf and is left as a refinement); (3) the trailing window is measured from the VERIFIER CLOCK: windows [u, u+n) with now < u + 5n; via the anchored engine only windows with u + n > A.slot are ever consulted, and since A ∈ suffix, every consulted window ends strictly after the claim tip cl.tipSlot — the certified prefix touches consulted windows only through its last n-1 slots, i.e. exactly the cl.tail buffer; (4) reusable as-is via the reconstruction: groundedCertK_suffix_history, exists_signedChain_of_covered, AttestedHistoryK, honestSlotsUnique_keyrot_anchored, horizon_shared_prefix, idInjective_keyrot, versionedUnforgeable_of_keyStealingEUFCMA, slot_le_tip_of_mem, deep_block_span (Molt), and the census lemmas (they are already generic in the witness chain c₀, so they apply to any attested history unchanged); (5) state it as a COROLLARY of a chain-level theorem applied to the reconstructed chains — but the existing chain-level anchored theorem (keyrot_recent_tip_ancestor_agreement_anchored) is tip-shaped and fixes hHash over KeyStealingSigned, so one new generic-Signed, arbitrary-depth anchored engine (keyrot_deep_block_agreement_anchored, ~80 lines, composed from existing lemmas) is added first; nothing is re-proved from the record.

## risks (verbatim)

1. **Risk:** Anchor-in-suffix is a protocol constraint on the prover (the suffix must start at or before the client's anchor); a reviewer may object that a certificate can 'swallow' the anchor and then the client has nothing to check.
   **Mitigation:** State it explicitly in the docstring and the paper edit: under the sync rule the anchor is < 4n slots old, so the required suffix is O(n) blocks; a client rejects any (certificate, suffix) pair whose suffix does not contain its anchor, exactly as the full-chain client rejects chains not containing it. If reach into the tail buffer is wanted, add groundedCertK_suffix_history_tail (copy of KeyStealingCert.lean:462-527 also returning hist.tail_eq, ~90 lines) and weaken hA to A ∈ cl.tail ++ s₁ :: srest — an additive follow-up, not a redo.
2. **Risk:** The anchored budget is still quantified over AttestedHistoryK (every history the first certificate could attest) because badKeyrotOn reads inForce over the full reconstructed chain; someone may expect the trailing form to make the budget verifier-visible from (fl, suffix).
   **Mitigation:** Document precisely: inForce (c ++ suffix) i s ≥ fl i holds only for s ≥ cl.tipSlot + Δconf (confirmedPrefix then contains all of c; keyFloor_le_extend), while for smaller s the confirmed prefix cuts inside the certified prefix and fl is only an UPPER bound — so a floor-snapshot budget predicate is sound (implies the AttestedHistoryK one) only above cl.tipSlot + Δconf. Left as a named refinement; the existing global certificate theorem has the same status.
3. **Risk:** Guard docstrings for the two long core names (MoltPetit.Model.keyrot_deep_block_agreement_anchored, MoltPetit.Model.keyrot_certified_suffix_agreement_anchored) must reproduce Lean's ~100-column wrap byte-for-byte (cf. Results/Axioms.lean:596-598).
   **Mitigation:** Run `#print axioms` first, paste the emitted message; do not hand-write. Molt.-prefixed names fit on one line.
4. **Risk:** Build discovery: new files are not elaborated by `lake build` unless imported from MoltPetit.lean / Molt.lean.
   **Mitigation:** Add the three root import lines (permitted) and, during development, build explicitly with `/etheron-pod/toolchains/lake.sh build MoltPetit.Model.KeyStealingCertAnchored Molt.CertClientRule Molt.AxiomsCertAnchored`.

   **Mitigation:** Place it in Molt/CertClientRule.lean as designed; the core file holds only the H-free anchored engine and corollary, which need nothing from Molt/. This matches the existing split (client_refresh_rule/stay_recent_client_safe are Molt-only).

## alternatives_rejected (verbatim)

1. **Alt:** Cheapest corollary: apply keyrot_recent_tip_ancestor_agreement_anchored (KeyStealingHorizon.lean:134) directly to the reconstructed signed chains, adding no chain-level lemma.
   **Why:** It fixes hHash over KeyStealingSigned (∃-version), a STRICTLY STRONGER hash assumption than the SignedDeclared domain of keyrot_recent_certified_suffix_agreement (SignedHashInjective is antitone in the domain; keyStealingSigned_of_declared goes the wrong way), and yields only the tip-shaped conclusion (block n below equal-height tips), losing the arbitrary-depth (i, i', hHeight) shape that the TS/Results consumers of the certificate theorems use. The generic-Signed, arbitrary-k engine costs ~80 copied lines and removes both defects. Kept as the fallback if the planner wants the absolute minimum.
2. **Alt:** Re-prove the certificate theorem directly on a SlotRecord (the recent_certified_suffix_agreement style in Grounded.lean:371).
   **Why:** No benefit: the key-stealing engine (honestSlotsUnique_keyrot_anchored + horizon_shared_prefix) is already stated over chainUnionRecord of signed chains; the reconstruction route is the established idiom of KeyStealingCert.lean and reuses everything.
3. **Alt:** Anchor via the claim tip (client checks cl.tipId = A.id ∧ cl.tipSlot = A.slot ∧ cl.tipHeight = A.height).
   **Why:** GroundedHistoryK.tip only relates the reconstructed tip block to A by id/slot/height; equality as a Block needs id-injectivity with A in the record, which A is not unless it is in a suffix anyway. Messier and not stronger than suffix membership.
4. **Alt:** Anchor anywhere in the verifier-visible blocks cl.tail ++ suffix.
   **Why:** Needs a copied reconstruction lemma exposing hist.tail_eq (groundedCertK_suffix_history returns only valid/head/len/signed), ~90 lines for at most n-1 extra blocks of reach. Deferred; listed as an open question and additive follow-up.
5. **Alt:** A verifier-visible budget predicate computed from (fl, suffix) instead of AttestedHistoryK.
   **Why:** Sound only for slots s ≥ cl.tipSlot + Δconf (below that the confirmed prefix cuts inside the certified prefix, where fl is an upper bound on inForce, the wrong direction). A refinement with its own design, not this item.
6. **Alt:** Previous sync given as a full chain scPrev (stay_recent_client_safe's exact shape) instead of a certificate triple.
   **Why:** Fewer hypotheses, but dishonest for a certificate-only client, which never holds a full chain; the cert form costs one AcceptedSuffixK bundle plus the same three anchor/cadence facts. Offered as an open question in case the owner prefers the hybrid.
7. **Alt:** Put the trailing-5n theorem in the core namespace.
   **Why:** deep_block_span is Molt-only and its countP helpers are private; a core version would need a ~100-line re-proof or an inverted import (core importing Molt).
8. **Alt:** Extend Molt/Axioms.lean and fix the stale docstring at Molt/Rotation.lean:303-307.
   **Why:** Forbidden by the additive rule; a new guard file and a superseding docstring in the new module are used instead.
